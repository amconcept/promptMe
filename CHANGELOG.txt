RANDO CALRISSIAN - CHANGELOG & FEATURES
========================================
(formerly "PromptMe App" - repo folder and some code identifiers still use the old name)

Version: 2026.7
Last Updated: August 2026

OVERVIEW
--------
Rando Calrissian is a creative prompt generation tool that lets a teacher combine one
objective with up to four prompts, optionally organized into groupings, and draw random
combinations without repetition. Four components:
- Editor (editor.html + modular JS): creating and managing activities
- Prompting window (sketch.html + modular JS): generating and displaying prompts
- Customize (theme.html): theme presets + reveal-animation editor
- Index (index.html): landing page + first-visit welcome

Companion documents (read these first):
- RANDOMIZER_LOGIC_SPEC.md - required draw behavior (R1-R7, I1-I6, scenarios S1-S10)
- DESIGN_DECISIONS.md      - why visual/UX choices are the way they are (D1-D69) + future directions
- README.md                - how a teacher uses the app
- .cursorrules             - how to work on this project

TERMINOLOGY
===========
User-facing text says "grouping". Code and RANDOMIZER_LOGIC_SPEC.md say "category"
(identifiers: category, criterion, criterionLabels). This split is deliberate: the UI
wording was updated for teachers, the internal term was intentionally left alone so the
draw logic isn't destabilized. Do not "fix" one to match the other.

CURRENT FEATURE SET
===================

ACTIVITY DESIGN (EDITOR)
- Up to 4 prompts (MAX_PROMPTS) and 6 groupings (MAX_CATEGORIES)
- One objective per activity, shown under the name field on the leftover card (D-028)
- Options entered one per line per cell; drop or paste PNG/JPG onto a cell (D-015)
- Image thumbs sit inside the prompt box; drop from another window is captured (D-019)
- Dropped files are PNG/JPG if their first bytes say so; remote http(s) URLs are never fetched (D-020)
- Finder drop: box lights while a file is held over it; dragenter is claimed so Safari delivers the file (D-021)
- Prompt headings are optional; a blank heading is omitted on the card (D-018)
- Desktop grid layout; phone/narrow layout switches to a single-prompt cube (D-023)
- Eight themes, chosen on the Customize page (`theme.html`), saved per activity (D-024)
- Each preset can be tuned (ink, paper, stroke, leftover-card frame 0–8px, glow, font family, size, style) in this browser; factory palettes stay resettable. Card frame 0 removes the prompting-page outline (D-059). Ink/paper/stroke use four short web-color palettes (Pastel, Primary, Neon, Shades) spanning the Tune panel (D-030, D-033). The 8 cards are leftover-card thumbnails: **Save look** stamps the mix on that card, **Factory** recalls the original recipe, **Use on [activity]** stamps the look onto the open activity (D-033). Customize chrome shows the live look (D-026)
- Hidden `#theme-select` remains in the editor for legacy save/load reads; the visible Theme dropdown is gone
- Reveal animation: fill overlay (default geometric decoy, or a custom drawing) that **loops until STOP** (D-047). STOP plays a rapid gated low-tone glitch, then paper tiles lift over the result, then the land note (D-048). Teacher picks grid size (6–20) and frame count (2–12); a new animation starts at 6×6 with 2 frames (D-032). Lowering Frames parks extra drawings so raising it brings them back (D-041). Sketch plays those frames on the same 120ms clock as Customize Play (D-035). Each film frame plays a pentatonic note (C-1 through C3, or mute); click the name under a thumbnail to cycle (D-040, D-042, D-049). Land (Customize) is the ping when the prompts appear (D-046); default C2. Custom drawings play as painted (D-044). Custom frames sit centered above the draw grid; drag to reorder; Shift-click a range; Shift while drawing flips pen/eraser; Clear Frame / Reset All (D-031). Square cells centered in the card; empty cells are page background (D-028). One leftover-card preview for both modes; pixel palette defaults to theme ink (D-027). Copy to Next duplicates a frame onto the next slot. Saved in localStorage (`revealAnimation`) and downloadable as JSON; the prompting window plays it (D-025)
- Delete `[ X ]` uses the theme primary color, not a separate red (D5)
- Help & Instructions popup, deep-linkable via editor.html?help=1

PHONE CUBE EDITOR (editor-prompt-cube.js)
- Single-prompt view for phones and narrow windows
- Horizontal swipe or the chevron buttons move between prompts
- Vertical swipe (outside a text area) moves between groupings
- Gesture handler locks to one axis per gesture so text areas still scroll and button
  taps are not stolen
- "+" adds a prompt or grouping; badges show position within prompts and groupings

PROMPTING WINDOW
- Circular RUN button; becomes RE-RUN (dimmed) while a finished result is displayed
- GO TO NEXT confirms the current result and opens a fresh slot
- Keyboard: UP ARROW / Enter generate, DOWN ARROW confirms and advances,
  LEFT/RIGHT navigate students and browse history, SPACE interrupts a scramble in
  progress (it does not generate)
- First RUN plays the film in a loop; STOP plays the glitch land then the result (D-045, D-047, D-048). Space still aborts and clears. Empty Custom skips the film and scrambles letters (D-058)
- Image options fill-then-resolve like text (D-025); the overlay plays the saved film in a loop until STOP (D-035, D-047); STOP lifts paper tiles with rapid gated low tones then the land note (D-048); through those holes the words scramble and lock (D-052); custom film stays intact (D-044); one pentatonic note per film frame plus a designed land ping (D-040, D-042, D-049, D-046); empty Custom uses letter-scramble / flicker-dot instead of Default Pattern (D-058)
- Pictures fill leftover height on the leftover card after name, objective, labels, and text; `IMAGE_SLOT` is the floor (D-038)
- Prompt pictures are cover-cropped to the film square; they mosaic while tiles lift and do not grow past that square (D-053)
- Prompt labels mix toward paper so they recede from the chosen values (D-039)
- Reveal grid stays square and centered in the card; objective sits under the name field in sentence case, centered, with no 1–2-word last wrap line (D-028, D-061); prompts cluster below
- Re-running a finished result puts that student's options back and draws again (R5)
- Controls: screenshot, report, clear, edit

RANDOMIZATION
- Behavior is specified in RANDOMIZER_LOGIC_SPEC.md; prompt-generator.js cites the rule
  IDs (R2/R3, R4, R6, R7, I5) at the code sites that implement them
- One option per prompt per run, all from a single locked grouping
- In-play tracking is per prompt type across eligible groupings
- A prompt type's in-play set refreshes only when its eligible union is exhausted (all groupings, or the selected chips when Students pick grouping is on) (D-063)
- Students pick grouping (editor, 2+ rows): grouping labels are tappable in the prompting window; chips are radio — one grouping at a time, that row is forced (R7) (D-063, D-064)

STUDENT HANDLING
- Names are optional; unnamed runs are auto-labelled "Run 1", "Run 2", ...
- requireStudentNames is stored per activity and defaults to off
- Comma-separated entry ("Alec, Marc, Miles") builds a navigable list
- Position counter under the name field

REPORTS (PER ACTIVITY)
- Results are stored per activity in activityReports, not in one shared pile
- Switching activities persists the outgoing session before loading the incoming one, so
  activities never mix results
- "Restore Last Run" in the File menu reopens the most recent session
- Reports survive trips to the editor and are cleared only by "clear"
- Downloaded report includes date/time header, the objective, and activity settings
- Image options print as [image] (files are not in the report)
- Screenshots save a PNG of an individual result

FILE MENU
- New, Save, Save As, Share, Load, Restore Last Run
- Share writes quoted CSV so commas in sentences survive Load. Pictures download as a
  zip folder (activity.csv + media/) after a SHARE/CANCEL warning; no pictures → plain
  CSV. Load accepts .csv or .zip (D-057; D-015 still forbids binaries inside the CSV)
- Three classroom sessions restore if missing: SIMPLE, SOD+A, SOD+A w/ Groupings
  (physical / digital / textiles; Students pick grouping on for the last) (D-065, D-066)
- One prompt sample, Two prompt sample, and Design challenge are no longer auto-restored (D-062 superseded by D-066)

LANDING PAGE
- First-visit welcome names the three classroom sessions; editor opens SIMPLE and a short walkthrough (D-066)
- Shown once, remembered as randoCalrissianWelcomeSeen in localStorage

DATA PERSISTENCE
- localStorage is the source of truth for activity text, `img:` tokens, `selectedTheme`, `themeCustomizations`, and `revealAnimation`
- PNG/JPG blobs live in IndexedDB (`promptMeImages`); they are not stored in localStorage.
  Share with pictures packs them into a zip media/ folder (D-057), not into the CSV.
- Editor and prompting window sync via a promptDataUpdated custom event, and across tabs
  via the storage event
- Auto-save on edit; save paths preserve report data so editing prompts mid-session does
  not wipe student progress


DEVELOPMENT CONVENTIONS
=======================

CACHE BUSTING
- Twenty-three local module <script> tags carry ?v=20260830bw (nine on editor.html, ten
  on sketch.html, three on theme.html, one on index.html). After editing any of those
  modules, bump that value on all twenty-three together. theme-manager.js is tagged on
  every page so Macintosh paper-on-ink (D-050) cannot load from a stale untagged copy.
- Mismatched values load a mix of old and new modules and produce confusing bugs
- The Sample activity CSV fetch uses the same ?v= value as the tagged modules

DOCUMENTATION ROUTING
- CHANGELOG.txt: every shipped change gets an entry (bugs, features, UI tweaks, refactors)
- DESIGN_DECISIONS.md: a row only for a UI/UX choice a future session could mistake for a
  bug and revert. Routine visual tweaks are CHANGELOG-only. Retired decisions are struck
  through, never deleted or renumbered.
- RANDOMIZER_LOGIC_SPEC.md: same "decision, not log" test for draw/interactive logic
- README "For Developers": architecture and dev conventions, not UI, game logic, or history
- /review (.cursor/commands/review.md) compares those four docs to the code; report only

NO BUILD STEP
- Open the HTML files directly, or serve the folder: python3 -m http.server 8000
- Anything requiring compilation needs a design decision first

DEBUG LOGGING
- data-manager.js and sketch-refactored.js carry heavy logging, a mix of real diagnostics
  and residue from specific past bugs
- Pending a deliberate human pass; do not strip automatically
- See DESIGN_DECISIONS.md section 3 (Known drift)
