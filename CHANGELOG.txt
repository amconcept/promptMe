RANDO CALRISSIAN - CHANGELOG & FEATURES
========================================
(formerly "PromptMe App" - repo folder and some code identifiers still use the old name)

Version: 2026.7
Last Updated: July 2026

OVERVIEW
--------
Rando Calrissian is a creative prompt generation tool that lets a teacher combine one
objective with up to four prompts, optionally organized into groupings, and draw random
combinations without repetition. Three components:
- Editor (editor.html + modular JS): creating and managing activities
- Prompting window (sketch.html + modular JS): generating and displaying prompts
- Index (index.html): landing page + first-visit welcome

Companion documents (read these first):
- RANDOMIZER_LOGIC_SPEC.md - required draw behavior (R1-R7, I1-I6, scenarios S1-S10)
- DESIGN_DECISIONS.md      - why visual/UX choices are what they are (D1-D9) + future directions
- README.md                - how a teacher uses the app
- .cursorrules             - how to work on this project

TERMINOLOGY
===========
User-facing text says "grouping". Code and RANDOMIZER_LOGIC_SPEC.md say "category"
(identifiers: category, criterion, criterionLabels). This split is deliberate: the UI
wording was updated for teachers, the internal term was intentionally left alone so the
draw logic isn't destabilized. Do not "fix" one to match the other.

CURRENT FEATURE SET
===================

ACTIVITY DESIGN (EDITOR)
- Up to 4 prompts (MAX_PROMPTS) and 6 groupings (MAX_CATEGORIES)
- One objective per activity, shown at the top of the prompting window
- Options entered one per line per cell
- Desktop grid layout; phone/narrow layout switches to a single-prompt cube
- Eight themes, saved per activity
- Help & Instructions popup, deep-linkable via editor.html?help=1

PHONE CUBE EDITOR (editor-prompt-cube.js)
- Single-prompt view for phones and narrow windows
- Horizontal swipe or the chevron buttons move between prompts
- Vertical swipe (outside a text area) moves between groupings
- Gesture handler locks to one axis per gesture so text areas still scroll and button
  taps are not stolen
- "+" adds a prompt or grouping; badges show position within prompts and groupings

PROMPTING WINDOW
- Circular RUN button; becomes RE-RUN (dimmed) while a finished result is displayed
- GO TO NEXT confirms the current result and opens a fresh slot
- Keyboard: UP ARROW / Enter generate, DOWN ARROW confirms and advances,
  LEFT/RIGHT navigate students and browse history, SPACE interrupts a scramble in
  progress (it does not generate)
- Generate presses during the scramble animation are ignored
- Re-running a finished result puts that student's options back and draws again (R5)
- Controls: screenshot, report, clear, edit

RANDOMIZATION
- Behavior is specified in RANDOMIZER_LOGIC_SPEC.md; prompt-generator.js cites the rule
  IDs (R2/R3, R4, R6, R7, I5) at the code sites that implement them
- One option per prompt per run, all from a single locked grouping
- In-play tracking is per prompt type across all groupings
- A prompt type's in-play set refreshes only when its full union is exhausted

STUDENT HANDLING
- Names are optional; unnamed runs are auto-labelled "Run 1", "Run 2", ...
- requireStudentNames is stored per activity and defaults to off
- Comma-separated entry ("Alec, Marc, Miles") builds a navigable list
- Position counter under the name field

REPORTS (PER ACTIVITY)
- Results are stored per activity in activityReports, not in one shared pile
- Switching activities persists the outgoing session before loading the incoming one, so
  activities never mix results
- "Restore Last Run" in the File menu reopens the most recent session
- Reports survive trips to the editor and are cleared only by "clear"
- Downloaded report includes date/time header, the objective, and activity settings
- Screenshots save a PNG of an individual result

FILE MENU
- New, Save, Save As, Share, Load, Restore Last Run
- CSV export/import carries activity name, theme, background, objective, grouping labels,
  prompt headers, and all grouping content
- Sample activity loads from Sample-activity-2025-10-27.csv, which is its source of truth,
  and is restored to Activity History automatically if deleted

LANDING PAGE
- First-visit welcome popup explaining the objective/prompt/grouping model, with a link
  into Help & Instructions
- Shown once, remembered as randoCalrissianWelcomeSeen in localStorage

DATA PERSISTENCE
- localStorage is the source of truth
- Editor and prompting window sync via a promptDataUpdated custom event, and across tabs
  via the storage event
- Auto-save on edit; save paths preserve report data so editing prompts mid-session does
  not wipe student progress


DEVELOPMENT CONVENTIONS
=======================

CACHE BUSTING
- Every <script> tag carries a ?v= query parameter; current value is ?v=20260728a
- After editing any JS, bump the value on ALL script tags together across editor.html,
  sketch.html, and index.html (11 tags, one shared value by convention)
- Mismatched values load a mix of old and new modules and produce confusing bugs
- The same convention applies to the Sample CSV fetch

NO BUILD STEP
- Open the HTML files directly, or serve the folder: python3 -m http.server 8000
- Anything requiring compilation needs a design decision first

DEBUG LOGGING
- data-manager.js and sketch-refactored.js carry heavy logging, a mix of real diagnostics
  and residue from specific past bugs
- Pending a deliberate human pass; do not strip automatically
- See DESIGN_DECISIONS.md section 3 (Known drift)

DEVELOPMENT HISTORY (CONDENSED)
===============================
Earlier revisions of this file recorded every change as its own "(LATEST UPDATE)"
section, which produced many entries that contradicted each other as features were added
and then reversed. That history is condensed below; full detail is in git.

ARCHITECTURE
- Refactored a monolithic sketch.js and editor.js into the modular structure above
- Modules have grown substantially since the split (see FILE STRUCTURE for real counts)

RANDOMIZER
- Repetition prevention became always-on rather than a toggle
- Draw behavior was formalized into RANDOMIZER_LOGIC_SPEC.md (R1-R7, I1-I6)
- prompt-generator.js comments now cite rule IDs at the implementing code
- Fixed: in-play state keyed per prompt type across groupings, not per grouping
- Fixed: in-play refresh only on full-union exhaustion, never on grouping-local empty
- Fixed: a run locks to one grouping for all prompts

EDITOR UI
- Retro terminal aesthetic applied; editor orange, prompting window green (D1)
- Delete buttons render as [x] in brackets and follow the theme color (D4, D5)
- Column alignment resolved via a 120px offset matching grouping label + gap (D3)
- Objective section moved above the Add controls
- Settings/File/Theme consolidated into dropdown menus
- Phone cube layout added, later gaining swipe gestures
- Fixed: iOS bug where only one character registered when typing the objective, by
  replacing width-limiting on input.value with a hidden mirror span and soft trimming
- Terminology renamed from criteria/category to grouping in user-facing text only

PROMPTING WINDOW
- Generation key moved from 'A' to UP ARROW, then Enter added; Space became an interrupt
- Name entry gained comma-separated lists and arrow navigation
- Names became optional, with auto-labelled "Run 1" unnamed runs
- RUN restyled as a circular button; RE-RUN / GO TO NEXT states added so a teacher's eye
  is guided to advance rather than re-run
- Prompts repositioned lower beneath the objective
- Recalled prompts use the same text size as animated ones, fixing size jump on navigation

REPORTS
- Report data persists across editor visits
- Reports moved from one global pile to per-activity storage with session switching
- Download gained date/time headers and the objective for context
- Fixed: data loss where the editor's save path overwrote the whole localStorage payload,
  resetting student progress mid-session
- Fixed: duplicate students across report sections

ACTIVITIES
- Save/load with named activities and Activity History
- CSV export/import for teacher-to-teacher sharing, preserving activity name
- Sample activity always loads from its CSV; auto-restored to History if deleted
- Fixed: cube data being wiped on load, by refreshing the cube before saving

ONBOARDING
- First-visit welcome popup on the landing page
- Help & Instructions rewritten to cover prompting concepts, groupings, and all controls
  on both desktop and phone; deep-linkable via ?help=1
- App renamed Rando Calrissian in the UI


FUTURE DIRECTIONS
=================
Captured in DESIGN_DECISIONS.md section 4, not repeated here. Summary: multi-format
prompts including images (F1), invisible teacher curation extending the paused
